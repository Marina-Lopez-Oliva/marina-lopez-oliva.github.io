01_contexto

Fortificación integral del controlador de dominio

El proyecto agrupa todas las prácticas de hardening realizadas sobre Windows Server 2025 Datacenter en su rol de controlador de dominio para el IES Camp de Morvedre. El objetivo ha sido reducir la superficie de ataque, garantizar la confidencialidad de los datos mediante cifrado, centralizar la gestión de actualizaciones y asegurar el proceso de arranque desde la BIOS/UEFI hasta el sistema operativo.

Se han aplicado líneas base de seguridad de Microsoft (Security Compliance Toolkit), deshabilitado servicios innecesarios, configurado el firewall de host, implementado BitLocker y EFS, y fortalecido el arranque con Secure Boot, ELAM, Credential Guard y UAC. Además, se ha realizado un análisis de vulnerabilidades (CVE) y se ha desplegado WSUS para la gestión centralizada de parches.

02_arquitectura

Capas de seguridad aplicadas

FIRMWARE Y ARRANQUE (BIOS/UEFI)

  • Contraseña de administrador y de sistema (BIOS)
  • Deshabilitado Legacy Boot y activado UEFI puro
  • Secure Boot activado con claves PK/KEK/db/dbx
  • TPM 2.0 habilitado y configurado (sin bypass físico)
  • Chassis Intrusion activado (detección de apertura física)
  • Deshabilitado Wake on LAN, puertos USB no necesarios y NIC remota

SISTEMA OPERATIVO (WINDOWS SERVER)

  • Gestión de actualizaciones con WSUS (servidor interno)
  • Líneas base de seguridad importadas (Security Compliance Toolkit)
  • Deshabilitación de servicios innecesarios (AppReadiness, Audio, Bluetooth, etc.)
  • Firewall de host con reglas de entrada/salida para SSH, DNS, SNMP, HTTP/HTTPS
  • Políticas de contraseñas robustas (12 caracteres, complejidad, bloqueo tras 5 fallos)
  • Auditoría de inicios de sesión (EventID 4624/4625)

CIFRADO Y PROTECCIÓN DE DATOS

  • BitLocker en disco de datos (unidad F:) con XtsAes128 y UsedSpaceOnly
  • Copia de seguridad de la clave de recuperación (archivo y dispositivo externo)
  • EFS: cifrado de carpeta test_cifradoEFS y archivos personales
  • Exportación de certificado EFS antes de eliminar usuario
  • Comprobación de inaccesibilidad desde Ubuntu Live (disco cifrado)

SEGURIDAD AVANZADA (CREDENTIAL GUARD, UAC)

  • Credential Guard aislado por virtualización (evita Pass-the-Hash)
  • UAC configurado en nivel máximo (ConsentPromptBehaviorAdmin=2)
  • ELAM (Early Launch Anti-Malware) con DriverLoadPolicy=8
  • Verificación de firmas digitales de archivos de arranque (sigverif)
  • Arranque medido con TPM (documentado teóricamente)
03_implementación

Fases del proyecto de hardening

01

Auditoría de actualizaciones y gestión de parches

Análisis de vulnerabilidades de Windows Server 2025 mediante CVEDetails (CVE-2025-62221, CVE-2025-64678, etc.). Implementación de WSUS: instalación del rol, creación de grupo de equipos, GPO para redirigir clientes al servidor interno, sincronización de actualizaciones y verificación en cliente Windows 11.

CVEWSUSGPO
02

Reducción de servicios y firewall de host

Listado de servicios activos con PowerShell, identificación de 40+ servicios innecesarios (AppReadiness, Audio, Bluetooth, RemoteRegistry, etc.). Deshabilitación con Set-Service -StartupType Disabled. Configuración de firewall: bloqueo de NetBIOS, cambio de puerto RDP (3389→8989), deshabilitación de ping, restricción de RDP a IP específica (192.168.13.3), reglas para SSH, DNS, SNMP, HTTP/HTTPS.

PowerShelliptablesRDP
03

Líneas base de seguridad (Security Compliance Toolkit)

Descarga de Microsoft Security Compliance Toolkit. Uso de Policy Analyzer para comparar configuraciones. Importación de la línea base "Windows Server 2025 - Domain Controller" mediante LGPO. Aplicación de GPOs a las OUs correspondientes (Equipos, Usuarios). Verificación con gpresult /r. Adaptación al contexto educativo (sin bloqueo de USB ni restricciones horarias extremas).

LGPOPolicy AnalyzerGPO
04

Configuración del sistema y arranque seguro

Preparación de máquina virtual con UEFI y TPM 2.0. Configuración de arranque seguro mediante bcdedit: modo minimal, 2 procesadores, 4096 MB RAM, debug activado, timeout 10 segundos, sin GUI. Implementación de ELAM (Early Launch Anti-Malware) con DriverLoadPolicy=8. Verificación de firmas con sigverif. Configuración de Credential Guard y UAC avanzado.

bcdeditELAMCredential Guard
05

Cifrado con BitLocker y EFS

Cifrado rápido de disco F: con Enable-BitLocker -UsedSpaceOnly -EncryptionMethod XtsAes128. Adición de protector por contraseña y clave de recuperación. Verificación con Get-BitLockerVolume. Prueba de acceso desde Ubuntu Live (imposible). Cifrado EFS de carpeta test_cifradoEFS con usuario "cifrado". Exportación de certificado (PFX) antes de eliminar usuario. Importación del certificado y acceso exitoso a los archivos.

BitLockerEFScertificado
06

Auditoría y fortificación de BIOS/UEFI

Identificación de características de seguridad en BIOS Optiplex 5070 (versión, Secure Boot, TPM, contraseñas, Legacy Boot, etc.). Propuesta de fortificación: contraseñas de admin y sistema, deshabilitado Legacy, activado Secure Boot con PK, TPM sin bypass, Chassis Intrusion, deshabilitado Wake on LAN y USB no esenciales, deshabilitado BIOS downgrade. Aplicación práctica de las medidas.

BIOSUEFITPM
07

Particiones seguras y recuperación

Análisis de particiones del sistema: EFI System Partition (100 MB FAT32) para arranque UEFI seguro, Windows Recovery Environment (687 MB NTFS) para restauración sin medios externos, y partición del sistema (49 GB NTFS) aislada. Verificación con diskpart y fstab. Medidas de seguridad aportadas por cada partición.

diskpartrecovery
08

Políticas de contraseñas y auditoría

Configuración de políticas de contraseñas en Active Directory: longitud mínima 12 caracteres, historial 24, caducidad 90 días, bloqueo tras 5 intentos fallidos (60 minutos). Activación de auditoría de inicios de sesión para eventos 4624 (éxito) y 4625 (fallo). Verificación de bloqueo de cuenta y visualización en visor de eventos.

GPOauditoríaEventID
04_incidencias

Hallazgos críticos y medidas correctivas

HALLAZGO — Ventana de exposición por parches no aplicados

Las vulnerabilidades CVE-2025-62221 (CVSS 7.8, exploit conocido) y CVE-2025-64678 (CVSS 8.8) permanecían activas durante semanas antes de aplicar los parches de Microsoft.

SOLUCIÓN

Implementación de WSUS para automatizar la aprobación de parches críticos en menos de 48 horas. Establecimiento de una política de actualizaciones con ventana de mantenimiento semanal.

HALLAZGO — Servicios innecesarios activos por defecto

Más de 40 servicios inseguros o irrelevantes en ejecución (AppReadiness, RemoteRegistry, Audio, Bluetooth, etc.), ampliando la superficie de ataque.

SOLUCIÓN

Deshabilitación mediante PowerShell de todos los servicios no críticos para un controlador de dominio. Se redujo el número de servicios activos en más de un 30%.

HALLAZGO — NetBIOS y SMB expuestos

El protocolo NetBIOS estaba habilitado y el puerto RDP por defecto (3389) accesible, facilitando ataques de enumeración y fuerza bruta.

SOLUCIÓN

Deshabilitación de NetBIOS sobre TCP/IP, bloqueo de puertos SMB no necesarios, cambio de puerto RDP a 8989 y restricción por IP (solo 192.168.13.3).

HALLAZGO — BIOS sin contraseña y con Legacy Boot activado

Cualquier persona con acceso físico podía modificar la configuración de arranque, arrancar desde USB o deshabilitar Secure Boot.

SOLUCIÓN

Establecimiento de contraseña de administrador de BIOS, deshabilitado Legacy Boot, activado Secure Boot con claves PK, y deshabilitado el arranque desde dispositivos USB.

HALLAZGO — Datos sin cifrar en discos extraíbles

El disco de datos "Privado" (F:) no estaba cifrado, permitiendo el acceso a la información si se extraía físicamente.

SOLUCIÓN

Cifrado BitLocker con XtsAes128 y modo UsedSpaceOnly. Copia de seguridad de la clave de recuperación en archivo y dispositivo externo. Verificación de inaccesibilidad desde Ubuntu Live.
