01_contexto

Fortificación completa de un servidor web Ubuntu

El proyecto agrupa todas las prácticas de hardening realizadas sobre Ubuntu Server 24.04 en su rol de servidor web (Apache2) para el IES Camp de Morvedre. El objetivo ha sido auditar y mejorar la seguridad del sistema mediante la herramienta Lynis, endurecer el servicio SSH (autenticación por certificado, 2FA, fail2ban), enjaular procesos con AppArmor, proteger el gestor de arranque GRUB, cifrar el disco completo con LUKS (incluyendo desbloqueo remoto con dropbear) y configurar políticas de contraseñas robustas siguiendo estándares NIST y CIS.

Las implementaciones han elevado el hardening index de Lynis de 58 a 66, eliminando advertencias críticas y reduciendo la superficie de ataque del servidor.

02_arquitectura

Capas de seguridad aplicadas

SERVICIO SSH (HARDENING)

  • Autenticación exclusiva con certificados RSA 4096 bits (clave pública/privada)
  • Deshabilitado acceso root y autenticación por contraseña
  • 2FA con Google Authenticator (TOTP) + excepción por grupo (dep_informatica)
  • fail2ban: 3 intentos fallidos → bloqueo 3600 segundos
  • Configuración de algoritmos seguros: Ciphers, MACs, KexAlgorithms (SHA2-512/256)
  • Banner personalizado de advertencia legal
  • Timeout de sesión (30 min) y bloqueo por inactividad (5 min)
  • Logging detallado a /var/log/auth.log y análisis con lnav

APARMOR (ENJAULAMIENTO DE PROCESOS)

  • Perfil personalizado para /usr/sbin/apache2 en modo Enforce
  • Reglas de acceso: lectura permitida en /var/www/Publico/**
  • Deny explícito para /var/www/Privado/** (bloqueo desde kernel)
  • Resolución de conflictos iniciales (logs, librerías mod_ssl)
  • Comprobación mediante curl: acceso a Publico OK, a Privado bloqueado (403)
  • Logs de denegación en /var/log/kern.log

CIFRADO LUKS + LVM Y DESBLOQUEO REMOTO

  • Instalación de Ubuntu Server con particiones cifradas LUKS
  • Esquema de particiones: /boot/efi (FAT32), /boot (ext4), LUKS container con LVM
  • Volúmenes LVM: ubuntu--vg-lv--0 (/), ubuntu--vg-lv--1 (swap), ubuntu--vg-lv--2 (/home)
  • Desbloqueo remoto con dropbear: SSH ligero en initramfs, puerto 6545
  • Claves SSH para autenticación, comando cryptroot-unlock
  • Verificación de inaccesibilidad de datos sin clave (prueba con Ubuntu Live)

AUDITORÍA, GRUB Y POLÍTICAS DE CONTRASEÑAS

  • Auditoría con Lynis: identificación de 51 sugerencias, corrección de warnings (firewall, paquetes vulnerables, GRUB)
  • Protección de GRUB: contraseña para editar menú, hash de contraseña, permisos mínimos en archivos de arranque
  • Políticas de contraseñas en PAM: pwquality (longitud 15, 4 clases, difok=5, gecoscheck, badwords)
  • Caducidad en login.defs: 90 días máximo, 1 día mínimo, aviso 7 días
  • Bloqueo de cuenta con pam_tally2: 5 fallos → bloqueo 60 minutos
03_implementación

Fases del proyecto de hardening en Ubuntu

01

Hardening del servicio SSH

Generación de claves RSA 4096 bits en clientes Linux y Windows (ssh-keygen, PuTTYgen). Configuración de sshd_config: PermitRootLogin no, PasswordAuthentication no, PubkeyAuthentication yes, Protocol 2, AllowUsers admin@IP. Implementación de 2FA con libpam-google-authenticator y excepción por grupo. Instalación de fail2ban con jail específico. Configuración de algoritmos seguros (Ciphers, MACs, KexAlgorithms) y timeout de sesión.

ssh-keygen2FAfail2ban
02

Auditoría inicial con Lynis y análisis de logs con lnav

Ejecución de Lynis: hardening index 58, 51 sugerencias, warnings críticos (FIRE-4512: iptables sin reglas, PKGS-7392: paquetes vulnerables, BOOT-5122: GRUB sin contraseña). Análisis de /var/log/auth.log con lnav, filtrado de eventos sshd, detección de intentos de acceso fallidos y reconstrucción de línea temporal de accesos exitosos.

Lynislnav
03

Corrección de advertencias y mejora del hardening index

Configuración de firewall básico con ufw (reglas por defecto deny incoming, allow outgoing). Actualización de paquetes vulnerables (apt upgrade). Protección de GRUB con contraseña (grub-mkpasswd-pbkdf2). Ajuste de umask a 027 en /etc/login.defs. Verificación de mejoras: hardening index sube a 66, desaparecen warnings críticos.

ufwGRUBumask
04

AppArmor: enjaulamiento de Apache2

Creación de estructura /var/www/Publico/ y /var/www/Privado/. Generación de perfil para /usr/sbin/apache2 con aa-genprof. Edición manual del perfil añadiendo deny /var/www/Privado/** r. Carga del perfil en modo Enforce. Pruebas de acceso: curl a Publico → OK, curl a Privado → bloqueado (403). Verificación de logs de denegación en kern.log.

AppArmoraa-genprof
05

Instalación con cifrado LUKS y desbloqueo remoto

Máquina virtual con UEFI y TPM simulado. Instalación de Ubuntu Server con particiones: /boot/efi (100 MB FAT32), /boot (2 GB ext4), y el resto como volumen físico LUKS. Configuración de LVM sobre el contenedor cifrado: volúmenes para /, swap y /home. Instalación de dropbear en initramfs, configuración de IP estática, claves SSH, puerto 6545. Prueba de desbloqueo remoto con cryptroot-unlock.

LUKSLVMdropbear
06

Políticas de contraseñas y gestión de usuarios

Configuración de pwquality.conf: minlen=15, minclass=4, difok=5, gecoscheck, badwords. Edición de common-password para usar pam_pwquality.so y pam_pwhistory.so (últimas 5 contraseñas). Configuración de login.defs: PASS_MAX_DAYS 90, PASS_MIN_DAYS 1, PASS_WARN_AGE 7. Bloqueo de cuenta con pam_tally2 (deny=5, unlock_time=3600). Pruebas de cambio de contraseña y verificación de bloqueo.

PAMpwqualitypam_tally2
04_incidencias

Hallazgos críticos y medidas correctivas

HALLAZGO — Firewall sin reglas activas (FIRE-4512)

Lynis detectó módulos iptables cargados pero sin reglas, exponiendo todos los puertos del servidor.

SOLUCIÓN

Configuración de ufw con políticas por defecto: deny incoming, allow outgoing. Reglas específicas para puertos SSH (22445), HTTP (80), HTTPS (443).

HALLAZGO — Paquetes vulnerables (PKGS-7392)

Apache2 y librerías del sistema con vulnerabilidades conocidas sin parchear.

SOLUCIÓN

Ejecución de apt update && apt upgrade -y. Verificación con Lynis de que ya no aparecen paquetes vulnerables.

HALLAZGO — GRUB sin protección (BOOT-5122)

Cualquier usuario con acceso físico podía editar parámetros de arranque o acceder al modo recovery sin autenticación.

SOLUCIÓN

Generación de hash de contraseña con grub-mkpasswd-pbkdf2. Adición de superusers y password_pbkdf2 en /etc/grub.d/40_custom. Actualización de GRUB y verificación de protección.

HALLAZGO — Apache2 podía leer directorios privados

Sin AppArmor, cualquier vulnerabilidad en Apache permitiría acceder a archivos confidenciales fuera del directorio público.

SOLUCIÓN

Creación de perfil AppArmor para apache2 con reglas deny específicas para /var/www/Privado/. Carga en modo Enforce y verificación de bloqueo.

HALLAZGO — Disco sin cifrar (riesgo de extracción física)

Un atacante con acceso físico podía extraer el disco y leer todos los datos del servidor.

SOLUCIÓN

Reinstalación con cifrado LUKS completo (excepto /boot). Configuración de desbloqueo remoto con dropbear para evitar intervención física.
