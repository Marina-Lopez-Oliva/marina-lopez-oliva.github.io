01_contexto

El problema a resolver

La empresa ficticia HackerLearn, una consultora de ciberseguridad con 50 empleados, operaba con una infraestructura tecnológica obsoleta que comprometía su seguridad, rendimiento y productividad. Red plana sin segmentación, cuentas locales sin autenticación centralizada, página web en WordPress con vulnerabilidades, y sin herramientas colaborativas integradas.

El proyecto abordó una modernización integral en cuatro frentes: sistema de autenticación centralizado, rediseño completo de la red, migración de la web corporativa y despliegue de plataforma colaborativa.

02_arquitectura

Diseño de la solución

AUTENTICACIÓN CENTRALIZADA

  • Active Directory con Samba4 sobre Ubuntu Server
  • Integración de clientes Windows y Ubuntu en el dominio
  • Políticas de grupo (GPO) y gestión centralizada de permisos
  • Single Sign-On para todos los servicios internos

INFRAESTRUCTURA DE RED

  • Router MikroTik RB5009 como núcleo de red
  • VLAN 10 (Servidores) · VLAN 20 (Empleados) · VLAN 30 (Invitados)
  • QoS y control de ancho de banda por Queue Tree
  • Switches TP-Link TL-SG3210 gestionables + APs Ubiquiti UniFi

WEB CORPORATIVA

  • Migración de WordPress a Liferay (plataforma empresarial)
  • Despliegue en Docker para aislamiento y escalabilidad
  • Certificados SSL con Certbot + Let's Encrypt
  • Control de permisos de usuarios por roles

HERRAMIENTAS COLABORATIVAS

  • Nextcloud instalado en servidor interno
  • Integración LDAP con Active Directory
  • Gestión de ficheros, calendarios y comunicación
  • Autenticación 2FA para acceso seguro

04_incidencias

Problemas resueltos

PROBLEMA — AD en Ubuntu

Al crear el dominio Samba4, error por paquetes ausentes que impedían la inicialización del controlador de dominio.

SOLUCIÓN

Instalación manual de dependencias faltantes e identificación del paquete específico mediante logs de Samba. Dominio operativo tras reinstalación controlada.

PROBLEMA — Usuario dominio en Ubuntu cliente

Firefox no encontraba el directorio home del usuario de dominio por el formato usuario@dominio en la ruta.

SOLUCIÓN

Modificación de /etc/sssd/sssd.conf: ajuste de fallback_home a /home/%u y desactivación de use_fully_qualified_names.

PROBLEMA — Conflicto usuarios Nextcloud

Usuario administrador local con mismo nombre que usuario AD impedía el acceso al usuario de directorio.

SOLUCIÓN

Promoción previa de usuarios AD a administradores, eliminación del admin local duplicado y verificación de acceso con las cuentas del dominio.

PROBLEMA — App store Nextcloud inaccesible

La tienda de aplicaciones no cargaba desde la interfaz web, posiblemente por ausencia de certificado SSL válido en ese momento.

SOLUCIÓN

Descarga manual de los paquetes desde nextcloud.com/apps y transferencia al servidor para instalación por línea de comandos con occ.
