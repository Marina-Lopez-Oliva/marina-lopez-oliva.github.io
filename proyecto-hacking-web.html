01_contexto

Explotación de vulnerabilidades web y resolución de CTFs

Este proyecto agrupa todas las prácticas de hacking enfocadas en vulnerabilidades de aplicaciones web (OWASP Top 10) y la resolución de máquinas CTF que combinan técnicas de explotación web con escalada de privilegios y pivoting. Se han realizado actividades guiadas (PortSwigger, TryHackMe) y máquinas reales de Vulnyx y exámenes prácticos.

Las vulnerabilidades cubiertas incluyen: IDOR (Insecure Direct Object Reference), Path Traversal (6 variantes), Local/Remote File Inclusion (LFI/RFI), Cross-Site Scripting (XSS: reflected, stored, DOM, 6 niveles), Cross-Site Request Forgery (CSRF con bypass de Double Submit Cookie y SameSite), e Inyección SQL (UNION, boolean blind, time-based, con SQLMap).

Además, se han resuelto máquinas completas como SHOP (Vulnyx) (Blind SQLi → credenciales → SSH → escalada con perl + cap_setuid), Badbyte (TryHackMe) (FTP con clave SSH → túnel SOCKS5 → plugin wp-file-manager vulnerable → escalada), y los exámenes de pre-examen y examen 3 (pivoting, RFI, WordPress, wp-file-manager, escalada con awk y vim).

02_técnicas

Vulnerabilidades OWASP explotadas

IDOR + PATH TRAVERSAL (Actividad 18)

  • IDOR: Cambio de ID en /download-transcript/X.txt para obtener la contraseña de otro usuario (BurpSuite Repeater).
  • Path Traversal (6 labs PortSwigger): Bypass con rutas absolutas, secuencias anidadas (....//), doble codificación URL, validación de inicio de directorio y null byte bypass (%00).

FILE INCLUSION (LFI / RFI - Actividad 19)

  • LFI: Subida de reverse shell .php.png (doble extensión) e inclusión desde parámetro lang. Escalada con contraseña en directorio oculto y sudo find.
  • RFI: Vulnerabilidad en plugin gwolle-gb (versión 1.5.3) → parámetro abspath permite incluir wp-load.php remoto. Shell reversa y escalada con rename (Perl) sobrescribiendo /etc/passwd.

XSS (Actividad 20)

  • TryHackMe XSS room + 6 niveles de XSS game: reflected, stored en <blockquote> (imagen con onerror), DOM-based (hash de URL), time-based (?timer), javascript: pseudo-protocol, data:text/javascript.
  • Explicación detallada del DOM Based XSS (funcionamiento paso a paso).

CSRF (Actividad 21)

  • CSRF básico: enlace GET para transferencia bancaria.
  • Double Submit Cookie bypass: token predecible (Base64 del número de cuenta) e inyección de cookie desde subdominio.
  • SameSite=Lax bypass: cierre de sesión mediante enlace GET y modificación de cookie isBanned en ventana de 2 minutos.

SQL INJECTION (Actividades 22 y 23)

  • In-band (UNION): extracción de credenciales de tabla staff_users.
  • Blind boolean: endpoint /checkuser?username= con cambios en respuesta.
  • Blind time-based: función SLEEP(n) para extraer información carácter a carácter.
  • SQLMap: automatización de la máquina SHOP (Vulnyx) – detección de blind time-based, enumeración de base de datos Webapp, tabla Users, credenciales (bart, liam, mike, peter).

PIVOTING Y MÁQUINAS CTF (Actividad 24 + exámenes)

  • Badbyte (TryHackMe): FTP anónimo (clave SSH id_rsa) → crackeo con ssh2john → túnel SOCKS5 → descubrimiento de WordPress interno → wp-file-manager (CVE-2020-25213) → Meterpreter → escalada con contraseña en logs de bash.
  • Máquina SHOP (Vulnyx): Blind SQLi en login → SQLMap → credenciales → acceso SSH → escalada con perl (cap_setuid+ep) → persistencia.
  • Pre-examen: RFI en change_theme.php (shell reversa) → credenciales en config.php → usuario webuser → sudo awk → root → pivoting a red interna → index_old.html estático (sin explotación).
  • Examen 3: Máquina espigol (RFI, webuser, sudo awk) y máquina cibercamp (WordPress wp-file-manager, reutilización de credenciales, sudo vim → root).

04_hallazgos

Vulnerabilidades críticas y lecciones aprendidas

Path Traversal – Null Byte Bypass

La aplicación validaba extensión .png, pero con %00 se truncaba la cadena: ../../../etc/passwd%00.png

SOLUCIÓN / MITIGACIÓN

Validar rutas con funciones seguras (basename), no depender de extensiones y desinfectar caracteres nulos.

RFI en change_theme.php y gwolle-gb

Inclusión remota de archivos permitía ejecutar reverse shells en PHP.

SOLUCIÓN / MITIGACIÓN

Deshabilitar allow_url_include, usar listas blancas de archivos locales, actualizar plugins.

XSS DOM-based en el hash de la URL

El código JavaScript leía window.location.hash y lo insertaba en el DOM sin sanitizar.

SOLUCIÓN / MITIGACIÓN

Usar textContent/innerText en lugar de innerHTML, escapar datos de origen del cliente.

Double Submit Cookie token predecible

El token CSRF era el número de cuenta en Base64, fácilmente reversible.

SOLUCIÓN / MITIGACIÓN

Generar tokens criptográficamente aleatorios y asociarlos a la sesión, no predecibles.

Blind Time-Based SQLi en login de SHOP

El parámetro username vulnerable a SLEEP(5), permitiendo extraer información.

SOLUCIÓN / MITIGACIÓN

Usar consultas parametrizadas (prepared statements), no concatenar inputs.

Reutilización de contraseñas (webuser / wpuser)

La misma contraseña se usaba en base de datos y para el usuario del sistema operativo.

SOLUCIÓN / MITIGACIÓN

Políticas de contraseñas únicas por servicio, separación de credenciales.
