01_contexto

Metodología de adquisición forense (software y hardware)

Este proyecto agrupa cuatro prácticas fundamentales de análisis forense digital centradas en la adquisición de evidencias, tanto volátiles (memoria RAM) como no volátiles (discos, USBs), utilizando herramientas software (FTK Imager, DumpIt, Winpmem, dd, dc3dd, Guymager) y hardware especializado (clonadora Tableau TD2u). También se cubre el triaje DFIR (adquisición rápida de artefactos) con CyLR, FastIR y Wintriage.

Las actividades incluyen: (1) Adquisición de memoria volátil en Windows 10/7 con tres herramientas, incluyendo diferencias de arquitectura (32/64 bits), fichas de cadena de custodia y comparativas; (2) Adquisición de discos y dispositivos extraíbles con dd, dc3dd, Guymager y FTK Imager, comparando formatos RAW vs EWF; (3) Clonación hardware con TD2u (clonación física e imagen sobre archivo) con generación automática de hashes y logs; (4) Triaje DFIR en Windows 10 con CyLR, FastIR y Wintriage, comparando tiempo de ejecución, tamaño de extracción y nivel de intrusión.

02_técnicas

Métodos y herramientas de adquisición

ADQUISICIÓN DE MEMORIA VOLÁTIL (Práctica 1)

  • Preparación: máquina Windows 10/7 con tareas en ejecución (aplicaciones, navegación, YouTube).
  • FTK Imager: interfaz gráfica, genera archivos .ad1, .mem, .sys + hashes MD5/SHA1 automáticos.
  • DumpIt: línea de comandos (solo presionar 'y'), archivo .dmp, hash SHA256 automático.
  • Winpmem: línea de comandos, archivo .raw, no calcula hashes automáticamente.
  • Incompatibilidad 64/32 bits: necesidad de versiones específicas para cada arquitectura.
  • Elaboración de fichas de cadena de custodia con hashes MD5, SHA1, SHA256.
  • Adquisición desde hipervisores: VirtualBox (vboxmanage dumpvmcore → objdump → extracción RAW), VMware (.vmsn con vmss2core), Hyper-V (Debug-VM -InjectNonMaskableInterrupt), Proxmox (instantánea en vivo → .raw).

ADQUISICIÓN NO VOLÁTIL (Prácticas 2 y 3)

  • Linux (dd / dc3dd): copia bit a bit, dc3dd añade logs y hashes integrados. Verificación con diff de hashes.
  • Linux (Guymager): interfaz gráfica, soporte nativo EWF, hashes múltiples, verificación automática.
  • Windows (FTK Imager): adquisición de discos físicos en formato RAW o EWF, cálculo de MD5/SHA1.
  • Hardware TD2u: clonación sector por sector (Disk Clone) y creación de imagen forense sobre archivo. Generación automática de hashes y logs en el propio dispositivo. Independencia de SO.
  • Comparativa formatos RAW (copia bit a bit, universal, sin compresión) vs EWF (comprimido, metadatos incrustados, fragmentable).

TRIAJE DFIR (Práctica 4)

  • Escenario: equipo Windows 10 supuestamente infectado con malware.
  • CyLR: línea de comandos con parámetros (-of, -od). Más rápida (≈1 min), fichero .zip de 106 MB. Menor rastro en sistema.
  • FastIR: ejecución directa, genera carpeta con logs y hashes SHA256 por artefacto. Tamaño 24.4 MB.
  • Wintriage: interfaz gráfica, selección de artefactos (módulos), más pesada (741 MB) y más intrusiva, pero más completa.
  • Elaboración de fichas de cadena de custodia para cada herramienta.

04_hallazgos

Comparativas y lecciones aprendidas

Herramientas de volcado de RAM

FTK Imager: más completa (múltiples formatos, hashes). DumpIt: más simple y rápida. Winpmem: ligera pero sin hashes automáticos. Incompatibilidad 64/32 bits crítica.

RECOMENDACIÓN

Para peritajes judiciales, usar FTK Imager (por los hashes integrados y cadena de custodia). Para triajes rápidos, DumpIt o Winpmem.

dd vs dc3dd

dd es universal pero no genera hashes ni logs. dc3dd es una mejora forense con logs y verificación integrada.

RECOMENDACIÓN

Siempre que sea posible, usar dc3dd en lugar de dd para garantizar trazabilidad y cadena de custodia.

RAW vs EWF

RAW: copia bit a bit, universal, sin compresión. EWF: comprimido, con metadatos, fragmentable, pero requiere software específico.

RECOMENDACIÓN

Para archivo a largo plazo y eficiencia de almacenamiento: EWF. Para compatibilidad máxima: RAW.

Hardware TD2u vs Software

TD2u es independiente del SO, genera hashes automáticamente, es auditable y más fiable para peritajes judiciales. El software puede dejar rastros en el sistema investigado.

RECOMENDACIÓN

Para evidencias que deban presentarse en juicio, utilizar clonadora hardware TD2u o similar. El software es útil para análisis internos o triajes rápidos.

Triaje DFIR: velocidad vs profundidad

CyLR es el más rápido y ligero (106 MB, 1 min), Wintriage el más completo pero pesado (741 MB) e intrusivo.

RECOMENDACIÓN

Para una primera respuesta (IR): CyLR. Para un análisis más profundo en laboratorio: Wintriage o FastIR.
