01_contexto

Protección de la información crítica del centro educativo

Para garantizar la disponibilidad e integridad de los datos del IES Camp de Morvedre, especialmente del Active Directory (carpeta SYSVOL), se ha implementado un sistema de copias de seguridad basado en la regla 3-2-1 (adaptada a 3-1-1 por limitaciones de laboratorio). Se utiliza la herramienta Duplicati, que permite copias cifradas, comprimidas, programadas y con restauración granular.

El diseño incluye tres copias de seguridad: una en un disco local (unidad E: Backup), otra en un segundo disco local (unidad F: Privado) y una tercera en la nube (Google Drive). Cada copia está protegida con contraseña y se realizan pruebas de restauración para verificar la integridad de los datos.

Además, se han definido políticas de seguridad para las copias de seguridad (cifrado, control de accesos, etiquetado, verificación periódica) alineadas con las recomendaciones de INCIBE y buenas prácticas del sector.

02_arquitectura

Diseño de la solución de backup

POLÍTICAS DE SEGURIDAD (INCIBE)

  • Identificación de datos críticos: SYSVOL (Active Directory), documentación administrativa, datos de alumnos/profesores.
  • Frecuencia: copia completa semanal, incremental diaria.
  • Verificación de soportes y etiquetado (carpetas con fecha YYYY-MM-DD).
  • Cifrado de los datos o del disco destino.
  • Control de accesos: solo administradores pueden restaurar.
  • Pruebas de restauración periódicas.
  • Destrucción segura de soportes antiguos.
  • Documentación y concienciación.

DUPLICATI (HERRAMIENTA)

  • Interfaz web para configuración y monitorización.
  • Backups cifrados con contraseña maestra.
  • Compresión automática para ahorro de espacio.
  • Programación flexible (horario, días, periodicidad).
  • Destinos: disco local, segundo disco, Google Drive, OneDrive, etc.
  • Restauración granular (archivos o carpetas concretas).
  • Registro detallado de operaciones.

DESTINOS DE ALMACENAMIENTO

  • Copia 1 (local): disco duro virtual E: (Backup) – 20 GB NTFS
  • Copia 2 (local alternativo): disco duro virtual F: (Privado) – otro medio físico simulado
  • Copia 3 (nube): Google Drive, carpeta "Backup-AD" – almacenamiento externo fuera del centro
  • Cifrado: cada backup tiene su propia contraseña (almacenada en gestor de contraseñas)
  • Programación: copias cada dos días a las 13h (disco E) y diaria a las 23h (Google Drive)
03_implementación

Proceso de implantación del sistema de backups

01

Instalación de Duplicati en Windows Server

Descarga del instalador desde la página oficial (duplicati.com). Ejecución del asistente de instalación. Configuración del servicio para que se inicie automáticamente. Acceso a la interfaz web (http://localhost:8200) para administración.

Duplicatiinstalación
02

Configuración de la primera copia de seguridad (disco E:)

Creación de un nuevo backup con nombre "Backup-AD1". Selección de directorio destino: E:\. Cifrado con contraseña (AES-256). Selección de origen: carpeta SYSVOL (C:\Windows\SYSVOL). Programación: cada 2 días a las 13:00 (lunes, miércoles, viernes, domingo). Ejecución manual inicial y verificación de archivos generados.

cifradoprogramación
03

Configuración de la segunda copia de seguridad (disco F:)

Mismos pasos que en la fase 2, pero con destino F:\ (disco "Privado"). Nombre "Backup-AD2". Mismo origen SYSVOL, misma programación (para tener redundancia local en otro disco). Verificación de la copia generada.

redundancia
04

Configuración de la tercera copia en Google Drive (nube)

Selección de destino "Google Drive". Autenticación mediante OAuth (AuthID). Creación de carpeta "Backup-AD" en Drive. Configuración de origen: archivo de prueba (debido a limitaciones de espacio) o SYSVOL simulado. Programación diaria a las 23:00. Cifrado con contraseña diferente. Verificación de subida y archivo en Drive.

Google Drivenube
05

Pruebas de restauración (validez de los backups)

Para cada una de las tres copias, se realiza una restauración de prueba. En Duplicati se selecciona "Restore" → "Direct Restore from Backup Files". Se elige el origen (disco o Drive), se introduce la contraseña, se selecciona el archivo/carpeta a restaurar y se elige la ubicación de destino (original o alternativa). Se verifica que la restauración sea exitosa y que los datos sean legibles.

restauraciónvalidación
06

Documentación y políticas de seguridad

Elaboración de un documento con las políticas de backup (frecuencia, responsables, cifrado, procedimiento de restauración, pruebas periódicas). Se recomienda la realización de simulacros trimestrales de restauración completa del AD.

04_incidencias

Hallazgos y medidas correctivas

HALLAZGO — Espacio insuficiente en Google Drive para SYSVOL completo

La carpeta SYSVOL ocupaba varios GB, superando el espacio disponible en la cuenta de Google Drive utilizada en el laboratorio.

SOLUCIÓN

Se optó por realizar la copia de un archivo de prueba representativo, documentando que en un entorno real se usaría una cuenta con capacidad suficiente o se comprimiría/cifraría con división en partes.

HALLAZGO — Autenticación OAuth para Google Drive desde Duplicati

La primera vez, el proceso de obtención del AuthID requería aceptar permisos y copiar un código de verificación.

SOLUCIÓN

Se siguió el asistente de Duplicati: se hizo clic en "Google Drive (limited) login", se aceptaron los permisos y se copió el código generado automáticamente. Se documentó el proceso para futuras configuraciones.

HALLAZGO — Ausencia de pruebas de restauración documentadas

En la organización no existía un procedimiento formal para verificar que las copias eran recuperables.

SOLUCIÓN

Se incluyó en el plan de seguridad la obligación de realizar pruebas de restauración mensuales, con registro de resultados (RTO/RPO real). Se realizaron pruebas exitosas en las tres copias.

HALLAZGO — Contraseñas de cifrado no gestionadas centralmente

Cada backup tenía una contraseña diferente, lo que podría provocar pérdida de acceso si no se almacenaban de forma segura.

SOLUCIÓN

Se implementó el uso de un gestor de contraseñas (Bitwarden) para almacenar las claves de cifrado de los backups, compartido con el equipo de administración.
